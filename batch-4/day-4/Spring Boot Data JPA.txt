Object Relational Mapping with Spring Boot
==========================================
-> how to work with relationships between entities in Spring Data
-> whenever multiple entities are coming into picture inside your application

1) One-to-One Relationship
2) One-to-Many Relationship
3) Many-to-One Relationship
3) Many-to-Many Relationship



1. @OneToOne: A single instance of one entity relates to exactly one instance of another entity (e.g., a User and a User Profile).

2. @OneToMany: A single instance of one entity relates to multiple instances of another entity (e.g., a Department and its Employees).

3. @ManyToOne: Multiple instances of one entity relate to a single instance of another entity. This is often the inverse side of a @OneToMany relationship and typically owns the foreign key.

4. @ManyToMany: Multiple instances of one entity relate to multiple instances of another entity (e.g., a student and multiple courses)


Fetch Types in Hibernate
------------------------
EAGER - Load the associated data of the other entity, before-hand which is bit costly.
LAZY - Load the associated data of the other entity, only when requested. This is done on demand.

Example: If we have a relationship between University and Student, when University data is fetched, we don't want to fetch students. Because, one university will have thousands of students in the students array in the mapping. It will be a very costly operation. So, we can tell hibernate to keep it with LAZY initialization.

Cascading in Hibernate - 
----------------------
Cascading in Hibernate refers to the automatic persistence of related entities. When a change is made to an entity, such as an update or deletion, the changes can be cascaded to related entities as well. 
Cascading in JPA coordinates actions between interconnected entities


Unidirectional vs. Bidirectional
================================
A relationship defined using Spring Data JPA can be either uni-directional, where only one of the related entities is aware that the relationship exists, or bi-directional, where both entities are aware of the relationship.

What does "aware" mean? In short, an entity that is aware of a relationship has a field that references the related entity

1. Uni-directional: Only one side of the relationship is aware of the other.
2. Bi-directional: Both entities have references to each other, allowing navigation in both directions.

In a uni-directional one-to-one relationship, only one of the entities is aware of and can access the other entity in the relationship. This contrasts with a bi-directional one-to-one relationship, where both entities involved are aware of each other and can mutually access each other's data.


==> Owning Side: The "owner" of the relationship is the entity responsible for managing the foreign key in the database.
In bi-directional relationships, the side without the "mappedBy" attribute is the owner.

Owning Side vs. Inverse Side: In any bi-directional relationship, one side is the "owning side" and manages the foreign key(s) in the database. The other side is the "inverse side" and uses the "mappedBy" attribute to indicate it does not own the relationship. JPA only considers the owning side when saving or updating relationships.

package com.modeln.mappings.oto.entity;
@Entity
@Data
public class Person {
	@Id
	@GeneratedValue(strategy = GenerationType.IDENTITY)
	private Integer personId;

	private String personName;

	private String personGender;

	@OneToOne(mappedBy = "person", cascade = CascadeType.ALL)
        @JsonBackReference
	private Passport passport;
}


package com.modeln.mappings.oto.entity;
@Entity
@Data
public class Passport {
	@Id
	@GeneratedValue(strategy = GenerationType.IDENTITY)
	private Integer passportId;

	private String passPortNum;

	private LocalDate issuedDate;

	private LocalDate expDate;
	
	@OneToOne
	@JoinColumn(name = "person_id")
	private Person person;
}
